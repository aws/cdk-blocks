# AWS CDK Blocks Dart – Agent Guide

Context for AI coding agents working in this directory.

## Project Overview

A code generator and runtime that turn an OpenRPC specification into a typed Dart client for an AWS CDK Blocks backend. Three pub packages under `packages/`:

- **blocks_runtime**: pure Dart (VM and web). JSON-RPC client, realtime channels over a shared WebSocket pool, file upload and download handles, the OIDC client (relay and loopback sign-in), session and token stores, and the error taxonomy.
- **blocks_codegen**: pure Dart, build time only. Parser, model builder and Dart code generator, exposed as a `build_runner` builder (`*.spec.json` to `*.blocks.dart`) and as a CLI (`bin/blocks_codegen.dart`).
- **blocks_runtime_flutter**: Flutter support. A Dart-only plugin that registers `FlutterSecureStore` (`flutter_secure_storage`) as the default session store before `main`, plus `FlutterBrowserLauncher` for OIDC sign-in.

Plus **example**, which is not published: the e2e suite. `run-e2e.sh` generates a client for `test-apps/native-bindings` into `example/lib/blocks_client.dart` (gitignored) and runs the suites in `example/bin/e2e/` against that backend.

Paths below are relative to `native/dart/` unless they say otherwise. Commands that start with `native/` or `scripts/` run from the repo root.

## Build and Test Commands

`blocks_codegen` and `blocks_runtime_flutter` resolve `blocks_runtime` from pub.dev unless a `pubspec_overrides.yaml` points them at the sibling package. That file is gitignored, so create it in every fresh checkout or worktree before `pub get` (CI does the same):

```bash
# From native/dart/
printf 'dependency_overrides:\n  blocks_runtime:\n    path: ../blocks_runtime\n' > packages/blocks_codegen/pubspec_overrides.yaml
printf 'dependency_overrides:\n  blocks_runtime:\n    path: ../blocks_runtime\n' > packages/blocks_runtime_flutter/pubspec_overrides.yaml
printf 'dependency_overrides:\n  blocks_runtime:\n    path: ../packages/blocks_runtime\n  blocks_codegen:\n    path: ../packages/blocks_codegen\n' > example/pubspec_overrides.yaml
```

Per package, in `packages/blocks_runtime` or `packages/blocks_codegen`:

```bash
dart pub get                                        # before dart format, or it can't resolve imports
dart format --output=none --set-exit-if-changed .   # CI fails on any change
dart analyze .                                      # advisory in CI; fix errors, warnings are not blocking
dart test

# blocks_runtime only: the browser tests CI runs
dart test -p chrome

# blocks_runtime only: regenerate lib/src/version.dart after a version bump (CI diffs it)
dart run build_runner build
```

In `packages/blocks_runtime_flutter`, use the Flutter tool for everything but formatting:

```bash
flutter pub get
dart format --output=none --set-exit-if-changed .
flutter analyze .
flutter test
```

Goldens, from the repo root. `regenerate-all.sh` regenerates the Kotlin, Swift and Dart goldens of every fixture in turn, so it needs the Kotlin and Swift toolchains too. To regenerate the Dart goldens alone, run the Dart step it runs:

```bash
native/codegen-fixtures/regenerate-all.sh

# Dart goldens only (from native/dart/packages/blocks_codegen)
REGENERATE_FIXTURES=1 dart test test/golden_file_test.dart

# Format-check and analyze every fixture's Dart golden (fails on errors and on any formatting change)
bash native/dart/scripts/analyze-fixture-goldens.sh
```

The e2e suite, from the repo root, after `npm ci` and `npm run build`:

```bash
native/dart/run-e2e.sh

# Against a deployed native-bindings sandbox: the OIDC suite runs only with RUN_OIDC=1
RUN_OIDC=1 native/dart/run-e2e.sh --blocks-url https://<api-id>.execute-api.<region>.amazonaws.com/prod/cdk-blocks/api
```

`run-e2e.sh` runs `npm run spec` in `test-apps/native-bindings`, generates `example/lib/blocks_client.dart` with the CLI, runs `dart analyze` on it, and then runs every suite listed in `example/bin/e2e_test.dart`. Without `--blocks-url` it starts the native-bindings dev server itself (`npx tsx cdk-blocks/scripts/server.ts`, log in `/tmp/blocks-e2e-server.log`) on a free port it picks, falling back to 3001, sets `BLOCKS_URL=http://localhost:<port>/cdk-blocks/api`, and stops the server on exit. Locally the OIDC suite always runs against the `Auth` block's stub IdP, so `RUN_OIDC` changes nothing. Against a deployed backend, seed the test user first (`npm run seed:cognito` in `test-apps/native-bindings`, see `example/README.md`); the suites skip the emailed-code legs there.

Repo-wide checks that cover this directory, from the repo root:

```bash
# Injection-sink guards; codegen.test.mjs scans blocks_codegen/lib
node --test scripts/sink-guards/allowlist.test.mjs scripts/sink-guards/regex.test.mjs scripts/sink-guards/shell.test.mjs scripts/sink-guards/workflows.test.mjs scripts/sink-guards/codegen.test.mjs scripts/sink-guards/html.test.mjs

# License headers on every tracked .dart and .sh file (--fix inserts missing ones)
npm run check:headers
```

## Package Dependency Rules

These constraints must be maintained:

| Rule | Reason |
|------|--------|
| `blocks_runtime` must NOT depend on Flutter | It runs in CLI tools, servers and web apps; its pubspec depends on `crypto`, `http` and `web_socket_channel` only |
| `blocks_runtime` uses `dart:io` only in `*_io.dart` files reached through a conditional import (`if (dart.library.io)`) | The package must compile for the web; CI runs `dart test -p chrome` on it |
| `blocks_runtime` must NOT depend on `blocks_codegen` or `blocks_runtime_flutter` | It is the runtime every app ships |
| `blocks_codegen` imports no `blocks_runtime` library | It runs at build time only. It names runtime types as strings (`blocksRuntimeTypeNames` and `_reserved` in `lib/src/builder.dart`, the `export … show` lists in `generator.dart`) so generated names don't collide with them |
| `blocks_codegen` depends on `blocks_runtime` only to pin a runtime the output supports | The constraint is `^minimumRuntimeVersion` (`lib/src/generator.dart`); `test/generator_test.dart` checks the two agree with `blocks_runtime/pubspec.yaml` |
| `blocks_runtime_flutter` imports only the public `package:blocks_runtime/blocks_runtime.dart` | Anything it needs from the runtime is public API, so apps can use it too |
| Generated code imports `package:blocks_runtime/blocks_runtime.dart`, plus the library of each native package the spec binds (`x-blocks-native-packages`) | Goldens and apps resolve nothing else; Flutter is never imported |

If you find yourself needing to break one of these rules, reconsider the approach.

## Codegen Invariants

| Invariant | Where it lives | Don't break |
|---|---|---|
| **Output is `dart format`-clean** (#1766). The generator builds unformatted source and runs it through `DartFormatter` from `dart_style` (the formatter `dart format` runs), for the output package's language version, under a `// dart format width=80` header. | `generator.dart::_format`, `generatedPageWidth`; `language_version.dart`; the CLI's `--language-version`. | Writing text after `_format`, or relying on hand layout. `test/dart_format_test.dart` and the format step of `analyze-fixture-goldens.sh` (with the `dart_style` constraint from the codegen pubspec) fail on any change. Bumping `dart_style` can reflow goldens: regenerate them in the same PR. |
| **Unknown enum values and union arms decode to `…Unknown`** (#1481). An enum or string-discriminated union that a result reaches is open: a sealed `X` with an `XKnown` enum and an `XUnknown` that keeps the value as sent, so it round-trips through `toJson()`. | `generator.dart::_openEnums`, `_openUnions`, `_emitOpenEnum`, `_emitSealedClass`. | Unions only parameters reach, boolean discriminators, and a union embedded in a hybrid arm stay closed. Fixtures `29-unknown-values`, `45-open-enums`; `test/open_enum_test.dart`, `test/open_union_test.dart`. |
| **One shared `AuthActionInput`, with deprecated aliases** (#1599). A parameter union the spec names with `x-blocks-type-name` takes that name in every namespace, so every `Auth` block's `setAuthState` takes the same type. The old per-namespace name (`AuthApiSetAuthStateInput`) stays as a `@Deprecated` typedef unless another type has it. | `builder.dart` (`DiscriminatedUnionRef(:typeName)`, `_hintedUnions`, `deprecatedAliases`); `generator.dart` emits the typedefs. | Fixtures `18-hybrid-arm`, `44-shared-union-type-name`. Removing an alias is a major change. |
| **Transferable parameters are refused.** A parameter that holds a realtime channel, file handle or OIDC client at any depth fails generation: the runtime classes are read-only and have no `toJson()`. Kotlin refuses the same parameters. | `generator.dart::_checkNoTransferableParams`. | Fixture `35-transferable-parameters`, whose Dart golden is `dart/codegen-error.txt`; `test/transferable_parameter_test.dart`. |
| **Generated names never collide.** A spec name becomes an identifier in one place; a keyword, a name the generated code refers to, a top-level name of the library or a member of the scope takes a trailing `$` (`class$`, `toJson$`). Two inline types that claim one name are suffixed with a warning, or fail with `NamingConflictException` under `fail_on_collision`. Two namespaces that would generate one `…Api` class always fail (#1573). A bound native type the library also declares fails. | `generator.dart::_identifiers`, `_declaredNames`, `_checkBoundTypesNotShadowed`; `identifiers.dart` (`dartIdentifiers`, `referencedNames`, `generatedTopLevelNames`); `builder.dart` (`NamingConflictException`, `apiClassNamesOf`). | Renaming a name that collides with nothing: existing output must not change. Fixtures `32-name-collisions`, `38-generated-name-collisions`; `test/collision_test.dart`, `test/local_name_collision_test.dart`, `test/reserved_name_test.dart`. |
| **Runtime error types are re-exported.** Every generated library re-exports `ApiException`, `BlocksException`, `ClientClosedException`, `TransportException` and `isBlocksError`, the realtime, file and transferable exceptions when the spec uses a transferable, and the OIDC types when a result holds an OIDC client, so an app needs only the generated import. | The `export 'package:blocks_runtime/blocks_runtime.dart' show …` lines in `generator.dart::generate`. | A name in a `show` list must exist in the runtime's public exports. Add a new public runtime type an app must catch to the matching list, and to `blocksRuntimeTypeNames` in `builder.dart`. |
| **Generated code names the oldest runtime it needs.** Each library's header says `Requires blocks_runtime <minimumRuntimeVersion> or later.` | `generator.dart::minimumRuntimeVersion`. | Raise it, with the codegen's `blocks_runtime` constraint, in the release whose output starts calling a new runtime API. |

## Common Workflows

### After changing the parser, the model builder or `generator.dart`

1. In `packages/blocks_codegen`: `dart format --output=none --set-exit-if-changed .`, `dart analyze .` and `dart test`.
2. If the output changed: regenerate the goldens with `native/codegen-fixtures/regenerate-all.sh`, or the Dart step alone. Only `../codegen-fixtures/*/dart/` may change; a Kotlin or Swift golden diff means the change reached a spec or another generator, so find out why before you continue. Review the Dart diff. Never hand-edit a golden or change an existing `spec.json` (see `../codegen-fixtures/AGENTS.md`).
3. Run `bash native/dart/scripts/analyze-fixture-goldens.sh`. The golden test only compares text; this formats and analyzes every golden against the in-repo runtime.
4. Run the sink guards. Their allowlists pin a reviewed site by file and full source text, not by line. If you edited the text of a pinned line in `generator.dart`, update that entry's `site` to the new text exactly as the failure report prints it; if you added a site, route the value through `_dartStringLiteral()` instead of allowlisting it.
5. Run `native/dart/run-e2e.sh`, which generates and analyzes a client for the native-bindings spec and runs it against the dev server.

### After changing the runtime

1. In `packages/blocks_runtime`: format, analyze, `dart test` and `dart test -p chrome`.
2. Run `native/dart/run-e2e.sh`.
3. If you changed the HTTP path, OIDC or realtime against API Gateway, also run the e2e suite against a deployed native-bindings sandbox (`--blocks-url` with `RUN_OIDC=1`), and tear the sandbox down afterwards (`npm run destroy` in `test-apps/native-bindings`).
4. Keep behavior aligned with the Kotlin and Swift runtimes. Only the codegen goldens check cross-SDK parity; nothing checks the runtimes.
5. If you added a public type an app catches or names, check the re-export lists in `generator.dart` (see Codegen Invariants).

### After changing the Flutter plugin

1. In `packages/blocks_runtime_flutter`: `flutter pub get`, `dart format --output=none --set-exit-if-changed .`, `flutter analyze .` and `flutter test`.
2. If you changed a class a test mocks, regenerate the mocks with `dart run build_runner build` and commit the `*.mocks.dart` files.
3. Plugin registration does not run under `flutter test`, so secure storage, the browser launcher and redirect handling need a run on a device or desktop app before release, with the platform setup from `packages/blocks_runtime_flutter/README.md`.

## Versioning and Changelogs

Dart has no changesets: `changeset-check-native.yml` checks only Kotlin and Swift. Each package has its own hand-edited `CHANGELOG.md`, and its version lives in its `pubspec.yaml`.

- Add entries under `## Unreleased` at the top of each changed package's `CHANGELOG.md`. Never name an unreleased version; the release PR turns `## Unreleased` into the version heading.
- Never change anything at or below the latest released heading (`## 1.0.0` today). Those entries are what pub.dev shows for releases already published.
- After a merge or rebase, check that your entries are still under `## Unreleased`. A merge can place an added bullet under the released heading when the surrounding lines match.
- The `^1.0.0` pins in `README.md` and the package READMEs track the published version. Change them in the release PR, not before.
- A version bump in `blocks_runtime/pubspec.yaml` needs `dart run build_runner build` to regenerate `lib/src/version.dart`; the `version-constant` job in `.github/workflows/native-dart-analysis.yml` fails otherwise.

1.0.0 is released, and apps depend on `^1.0.0`, which takes every release below 2.0.0. Pick the version by what an app on the previous release sees:

| Bump | Use for |
|------|---------|
| major | Anything source-breaking: a removed or renamed public declaration or generated type, a changed signature or return type, a new subtype of a sealed class or a new enum value an exhaustive `switch` must handle, a raised minimum Dart or Flutter SDK, or a behavior change a caller must handle |
| minor | New public API that existing code keeps compiling against, or a deprecation |
| patch | Fixes and internal changes with no public API change |

Flag a major change for maintainer review, and remove a deprecated API only in a major release.

## Gotchas

- **Stage prefixes.** A deployed API Gateway URL carries its stage (`/prod/cdk-blocks/api`). An e2e assertion on an exact path, such as a logout URL's `path`, passes locally and fails in the sandbox job. Compare against the base URL's path, not a literal.
- **Sink-guard pins.** The allowlists name sites by source text. Rewording, reformatting or splitting a pinned line breaks its entry even when the code is equivalent. Update the pin to the new text; never pin by line number.
- **Golden conflicts.** Goldens from two PRs that both change generator output conflict on rebase. Take either side, regenerate, and review the result; never resolve a golden conflict by hand.
- **macOS entitlements.** A Flutter macOS app needs `com.apple.security.network.client` to reach the backend and `keychain-access-groups` for the secure store, in both `DebugProfile.entitlements` and `Release.entitlements`, plus `com.apple.security.network.server` in `Release.entitlements` for loopback sign-in. Without the network entitlement every call throws `TransportException`.
- **`pubspec_overrides.yaml`.** It is gitignored. A fresh worktree resolves `blocks_runtime` from pub.dev, and `example` fails `pub get` with a hosted/path conflict, until you recreate the files (see Build and Test Commands). `run-e2e.sh` hides `pub get` output, so a missing override shows only as the script stopping at "Verify generated client compiles".
- **Route prefix.** The API is served under `/cdk-blocks/` (`/cdk-blocks/api`, auth routes under `/cdk-blocks/auth/*`). `/aws-blocks/` is a legacy alias (`LEGACY_BLOCKS_NAMESPACE` in `packages/core/src/constants.ts` at the repo root). Use `/cdk-blocks/` in code, tests and docs.
